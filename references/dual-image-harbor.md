# Current dual-image Harbor handoff

Use this when the active program follows the 2026-09-29 *AutoResearch 专家线下标注教程｜PCA 双镜像对齐版*. Re-read any later tutorial and the installed Harbor/provider schema before implementation. The earlier `规范格式.docx`, event-interpolation `example/`, and 2026-09-18 QA Docker path contract describe an older single-image layout; QA v0.3.1 (2026-09-30) supports this dual-image profile. The PCA appendix illustrates the new roles but explicitly lacks formal paired runs, long trajectories, two built images, a complete Harbor handoff, and normalized-score acceptance. Its PCA algorithm, `schema_version="1.3"`, resource values and Dockerfile internals are not universal defaults.

## Two build contexts and three visibility domains

`workspace/harbor_task/` is the platform task root, not a directory mounted wholesale into the Agent. Its `instruction.md` reaches the Agent through the harness. `environment/Dockerfile` builds the Agent image with **`environment/` as context**. It copies only declared public dependencies, `starter/`, Public/Dev scorer (for example `public_eval/`) and public assets. At runtime initialize a read-only Starter and an editable `/workspace/solution` from the same source, or implement an equivalent declared initialization. Do not treat a source-tree `harbor_task/solution/` as the Agent build input or confuse it with Harbor's optional Oracle directory.

`tests/Dockerfile` builds the **separate Verifier image with `tests/` as context**. It contains `/tests/test.sh`, trusted scoring code, its own dependencies and authorized private data or generators. The final grader runs after the Agent exits. Hidden evaluation material is required for training and non-training tasks; it may be prebuilt into the image, generated there under fixed rules, or securely injected by the platform. Record the material's source, preparation and actual scorer call path, with implementation or platform evidence for injection. No particular directory name, empty directory or placeholder file is required. Neither Dockerfile may use out-of-context `COPY ../` or copy the whole expert submission into the Agent image. Build both images and record their identities; an Agent image build alone is insufficient.

The expert-side `workspace/reference/`, optimization evidence, completed expert evidence and owner report stay outside the Agent view. If final scoring genuinely needs a reference algorithm, put only the required, independently protected copy in the private Verifier build context and prevent the candidate process from reading it. The private reference used by trusted grading must not silently become an Agent hint.

## Public iteration and final handoff

The Agent runs Public/Dev scoring inside its image after each method edit. `environment/public_eval/` is one suitable name; an equivalent public callable entry is allowed. It returns useful machine-readable feedback under the declared public split. It must implement compatible metric definitions, validity rules and quality gates with the final grader while keeping split-specific assets and B/U anchors distinct. The `separate` Verifier does **not** provide a per-iteration hidden-score service, and images should not rebuild every iteration.

Before exit, the Agent restores its best Public/Dev-valid candidate, including any required checkpoint and configuration, to the declared `/workspace/solution` submission contract. Under the current tutorial, `task.toml` uses `artifacts = ["/workspace/solution"]`, `verifier.environment_mode = "separate"`, and a separately configured verifier environment when the installed version accepts those fields. Check that the artifact **source** paths cover every file the Verifier reads; Harbor's default `/logs/artifacts/` applies only to files actually placed there, and an artifact destination is a host collection path, not a remapping inside the Verifier. Validate parsing **and actual effect** in the target Harbor version; the sample TOML is not a portable schema guarantee. Transfer only allowlisted candidate files. Exclude Agent logs, reward, private grader, Reference and whole-workspace copies. Check size, type, links, immutable asset references and any frozen launcher before trusted scoring. If a required model lives elsewhere at exit, the handoff is incomplete even when source code is present.

After transfer, the independent Verifier runs `bash /tests/test.sh` without assuming its current working directory. It loads `/workspace/solution`, computes a trusted result and atomically writes finite `/logs/verifier/reward.txt` or a supported numeric `reward.json`. An Agent-provided score, stale reward, contract-only pytest, or script output alone does not satisfy the interface. Final/Hidden results are for independent acceptance and cannot select or revise the Agent's method. A single final Verifier execution does not imply that every Public/Dev round received a hidden score.

Candidate code remains **untrusted inside the private Verifier**. The trusted scorer may read labels, keys and private reference material; the candidate subprocess may receive only allowed inputs and cannot read that material, modify `/tests`, influence trusted imports, or write reward. Enforce with appropriate identity, filesystem/process restrictions or an equivalent mechanism. Do not import candidate Python into a privileged grader process and infer isolation merely from the two containers. Probe effective permissions as the candidate identity on the intended platform.

## Preparation evidence and honest status

For launch readiness, check the host can actually build/run both containers; a container-only cloud host may lack the required Docker nesting. A remote GPU reached through SSH remains possible only when code transfer, permissions, result return, model handoff and both-image Harbor topology work on the chosen hosts. Record each image's digest, build context, dependencies and resource/time limits. Keep one-score time, Agent job time, build/setup time and Verifier time separate.

Run a bounded non-search validation with a fixed legal candidate when authorized: Agent environment reaches Public/Dev feedback; Agent exits with the complete artifact; Harbor transfers only that artifact; the separate Verifier receives it and produces a trusted reward; candidate-private access probes and Agent-view checks show the declared isolation. Reconcile one Trial's config, task version or hash, image IDs, transferred-file manifest, verifier logs, reward file and result; matching task names alone do not prove the Trial used this task revision. A same-version NOP Trial is a recommended optional check of the harness path, not a substitute for valid-candidate scoring: a Starter may remain present, an early exit may skip grading, and a zero reward alone says nothing about correctness. If official Hidden access is unavailable, use authorized validation data through the **same interface** and state that official Hidden acceptance remains pending. Static parsing, two successful Docker builds, a direct grader run, and a historical example are different evidence levels.

QA v0.3.1 supports the `environment/` and `tests/` build contexts and treats source-tree `solution/` as optional Oracle material. Only if an **older** QA tool rejects a correct dual-image package for task-root context or missing source-tree `solution/`, report a policy-version mismatch and independently check the active contract. Preserve G/B/statistical requirements that this revision leaves in force.
